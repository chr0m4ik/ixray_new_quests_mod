# Запрос: слой-иконка поверх иконки предмета в ячейке инвентаря

**Что нужно**

Дать возможность рисовать поверх иконки предмета в ячейке инвентаря
дополнительную иконку, задаваемую в конфиге. Например, предмет «контейнер с
артефактом» должен показывать иконку контейнера, а поверх неё — уменьшенную
иконку лежащего внутри артефакта.

**Почему это нельзя сделать скриптом**

В Lua выведены `CUIWindow` (`AttachChild`, `SetWndPos`, `GetAbsoluteRect`),
`CUIStatic` (`InitTexture`, `SetTextureRect_script`) и `get_actor_menu()`
(`UIActorMenu_script.cpp`). То есть нарисовать слой технически есть чем, но
**нельзя узнать, где находится ячейка**: `CUICellItem` в Lua не выведена, а
`CUIWindow::GetChildWndList` / `FindChild` / `GetChildNum` не экспортированы —
обойти дерево окон и найти ячейку нечем.

Колбэки `OnItemFocusReceive` / `OnItemFocusLost` тоже не помогают: в Lua
передаётся игровой объект, а не ячейка (`UIActorMenu_action.cpp`):

```cpp
PIItem _iitem = (PIItem)itm->m_pData;
CGameObject* GO = _iitem ? _iitem->cast_game_object() : NULL;
if (GO) funct1(GO->lua_game_object());
```

Интерфейс `ICustomDrawCellItem::OnDraw(CUICellItem*)` существует, но задать
свою реализацию из скрипта нечем.

**Почему это логично именно в движке**

Ровно эта механика в движке **уже есть** — для обвесов оружия:
`CUIWeaponCellItem::CreateIcon` / `InitAddon` (`ui/UICellCustomItems.cpp`)
рисует иконки прицела, глушителя и подствольника поверх иконки ствола. Не
хватает её обобщения на обычную ячейку инвентаря
(`CUIInventoryCellItem`).

**Предлагаемая реализация (обобщение существующего кода)**

Те же приёмы, что и для оружия: `CUIStatic` как дочернее окно ячейки,
`InventoryUtilities::GetEquipmentIconsShader`, `SetTextureRect`, `AttachChild`.
Новых зависимостей нет — всё это уже используется в `UICellCustomItems.cpp`.

Ключи конфига (в секции предмета):

```ini
1icon_layer       = af_eye            ; секция, ЧЬЮ иконку накладываем
1icon_layer_texture = ui\ui_icon_equipment  ; необязательно; по умолчанию штатный атлас иконок
1icon_layer_x     = 24                ; смещение внутри клетки, px (при inv_scale = 1.0)
1icon_layer_y     = 24
1icon_layer_scale = 0.5               ; 0.5 -> значок 25x25 в клетке 50x50
```

Геометрию считать **не в конструкторе**, а на первом `Update()`: в конструкторе
ячейка ещё не имеет размера (`GetWidth()`/`GetHeight()` равны нулю) и слой
получится нулевым. Пересчитывать при смене `Heading` (разворот предмета
клавишей R).

**Почему это безопасно для других модов**

Логика полностью **условная**: слой создаётся только если в секции предмета
есть ключ `1icon_layer`. Нет ключа — код не выполняется вообще, поведение
движка не меняется. Новых обязательных ключей и изменений формата нет.

**Альтернатива, если обобщать не хочется**

Достаточно вывести в Lua `CUICellItem` и `CUIWindow::GetChildWndList`. Тогда
мододелы смогут делать такие слои сами, скриптами, и движок не будет
накапливать частные случаи. Для Lua понадобится `InitTexture` +
`SetTextureRect_script` у `CUIStatic` — они уже есть.

**Контекст**

- Платформа: IX-Ray 1.6 (S.T.A.L.K.E.R. Call of Pripyat), версия 1.3.6.
- Сейчас такое делают только предварительной компоновкой иконок: либо один
  общий атлас всех комбинаций (растёт как произведение числа предметов),
  либо отдельная текстура на каждую комбинацию. Оба пути избыточны и требуют
  перерисовки при добавлении нового предмета.
- В Anomaly этой проблемы нет, потому что там ячейка инвентаря рисуется
  скриптом (`UICellItem` в Lua), а не C++.
